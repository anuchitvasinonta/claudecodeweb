## What this is

The umbrella project. I'm 55, have achieved a few aspects in life — work,
financial. I run a small software company but not doing much with it lately,
and I'm a part-time consultant to a friend's company in fintech. My daughter
is a fourth-year undergrad in computer engineering at Chulalongkorn
University. I don't have to do a full-time job, and with my daughter quite
grown-up and independent, I have a bit of free time and want to make it
meaningful.

So this is my life-coaching project: designing what's best for me to do across
all aspects of life. Claude is the life coach.

Each gets its own project under `projects/` for the details. This project
holds the direction, not the detail.

  engineers set up and operate, and I don't plan to add new services to it.
  The opposite: I want to create, set up and operate something myself so I'm

- **Health** — e.g. a workout plan that takes in my feedback and keeps
  improving. Not started.
- **Keeping up with knowledge** — not started.
- **Relationships** — not started.

Agreed 2026-08-04: start with a few aspects rather than all four at once.

### Proposed by Claude — not yet agreed

Suggestions for when each aspect project gets created. Nothing here is
decided; it's here so the next session doesn't re-derive it.

- **Metrics are per-aspect and belong in that project's `log.md`.** Don't
  duplicate them here — this file goes stale the moment two places hold the
  same number.
- **Health:** weight is a fine daily-ish number, but BMI barely moves week to
  week and will read as failure when nothing is wrong. Consider pairing it
  with something that responds fast and reflects the actual plan — sessions
  completed per week, or a load/rep number you're trying to move.
- **Business:** revenue per month is the right end-state metric but will be
  zero for a while, which makes it useless as early feedback. Something
  upstream — conversations had, things shipped, prototypes tried — tells you
  whether the project is alive before revenue does.
- **Knowledge:** "things I learn that month" works as a list, not a count. A
  count rewards skimming.
- **Relationships:** the aspect where a metric is most likely to be fake. My
  suggestion is no number here — just a written note each review.
